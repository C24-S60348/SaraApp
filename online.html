Online multiplayer: what we need

Status: the Firebase project saraapp is set up. Pet Puzzle Battle online is live (press “Play online” in that game). Zuma Duo online is next.

Right now both games are local: two people share one screen. Online means two people on two different devices.

The one big thing to know

GitHub Pages only hosts files. It cannot run a game server. So for online play, the two browsers need a free “messenger” service in the middle. We do not need to rent or run a server ourselves.

Options

  • Firebase Realtime Database (Google). Free plan, no server, easy. Good for the turn-based Pet Puzzle, and fine for Zuma Duo too. Needs a Google account.
  • PeerJS / WebRTC. The two phones talk directly. No account, free, very low delay. Best for fast Zuma. Can fail on some strict mobile networks.
  • Our own server (Node.js on Render or Fly). Most control, but more to maintain and the free tier goes to sleep. Not needed for now.

My recommendation

  • One game, two modes (not two separate games). Keep one folder per game and add a menu choice: Local or Online. The rules stay the same, and every bug fix helps both. On the home page we can still show two cards, “Zuma Duo” and “Zuma Duo Online”, that open the same game with a different mode. Only split them into separate games if they become very different.
  • Start with Pet Puzzle Battle. It is turn-based, so we only send each move (“swap tile A with tile B”). Both devices share one random seed so the boards match. Small, cheap and reliable.
  • Then Zuma Duo. Player 1’s device runs the game. Player 2 sends only touches or aim, and receives the game picture data about 20–30 times a second. Using the same Firebase keeps setup simple. If it feels laggy we can switch to PeerJS.
  • Joining: one player creates a room and gets a 4-letter code. The friend types the code to join.

What you need to bring

  1. A free Google account (you can use the one you already have).
  2. Go to console.firebase.google.com and create a project (free “Spark” plan, no credit card). Name it anything, for example “saraapp”. You can turn Google Analytics off.
  3. Inside the project, add a Web app (the </> icon). Firebase then shows a block called firebaseConfig.
  4. Open Build → Realtime Database → Create database. Pick the region nearest to you.
  5. Send me the firebaseConfig block. It is not a password. It is meant to be public, so it is safe to put in the website. Never send me your Google password.
  6. I will give you short database “rules” to paste into the Rules tab so only room data can be used.
  7. Two devices (for example your phone and a laptop) to test with.

Good to know

  • The free plan allows about 100 people connected at the same time. That is plenty for you and your friends.
  • Anyone technical could cheat with browser tools. For a game with friends this is fine.
  • No user accounts or names are needed at the start. Players are anonymous with a room code.
  • Later ideas: names and avatars, a rematch button, and quick-match with a stranger.
